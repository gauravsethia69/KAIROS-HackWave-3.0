# Data & Analytics operating reference

## Status and primary responsibilities
This is a proposed operating description for Data & Analytics, not a claim that the department has accepted new work. The proposed remit is metric definitions, usage validation and evidence synthesis.

## Relevant workflow
Compare like-length periods using measured dates; inspect missing data and affected client-product combinations before suggesting causes. Start with source IDs and current ownership; distinguish completed work from open obligations.

## Records and relationships
Relevant records include product_usage, analytical projects and measurement issues. Actual employees are selected by employees.department_id. Their tasks and issues follow owner_employee_id; project ownership is a separate relationship and must not be inferred from task counts.

## Dependencies
Coordinate with Engineering for instrumentation; Product for success metrics; Customer Success for adoption context. Shared client_id, product_id and project_id relationships provide context, not implicit reassignment.

## Escalation
Propose contacting the assigned employee first, then their recorded manager if available. State missing owners or schedules explicitly. Only an approved company workflow may change an assignment or commitment.
